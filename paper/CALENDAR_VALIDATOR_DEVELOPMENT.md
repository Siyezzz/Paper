# Iteration 15: Calendar-aware ordinary-validator development comparison

This supplement reports a deterministic, author-designed development comparison on previously exposed MSFT, NVDA, and INTC annual source-grounded cases. It is not a learned model, LLM experiment, blind holdout, independent-author benchmark, or population-effect claim.

## Inputs and lock

The runner first loads the existing local source-grounded and issuer-transfer loaders. It verifies every stored source SHA-256 and the existing row-level extraction/oracle checks before constructing items. It then freezes the old admission state and creates a pre-execution lock containing source evidence, exact items, oracle targets, and implementation/config hashes. Every case verifies disk inputs before and after execution; executor mutation is rejected, and oracle targets are not passed to the executor. `--reproduce PATH` requires full JSON equality with a prior output.

Run from the repository root:

```text
python experiments/calendar_validator_development.py --out experiments/artifacts/iteration15_calendar/final_results.json
python experiments/calendar_validator_development.py --out experiments/artifacts/iteration15_calendar/final_reproduction.json --reproduce experiments/artifacts/iteration15_calendar/final_results.json
python -m unittest discover -s experiments -p 'test_calendar_validator.py'
```

## Ordinary rules

The validator requires explicit task semantics, issuer identity, annual period kind, adjacent fiscal-year integers, same issuer reporting convention, USD currency, GAAP total revenue metric, known positive multiplicative scale, availability by the selected date, and contiguous periods. MSFT uses an author rule accepting 365/366-day July 1–June 30 annual windows. NVDA/INTC use an author rule accepting 364/371-day 52/53-week annual windows with matching weekday starts. These duration rules are author acceptance rules, not source facts or broad proven thresholds. Week-year starts remain inferred metadata. The task semantics `constant_duration_fiscal_year_growth` additionally rejects unequal durations; ordinary reported-adjacent growth does not pretend unequal 52/53-week periods are constant duration.

The independent arithmetic oracle uses integer `Fraction` arithmetic and explicit ties-to-even rounding, independent of the tested validator. Targets are not passed to the executor. Unknown semantics, quarter/nonannual metadata, nonadjacent periods, convention mismatch, unavailable data, unknown scale, zero base, false fiscal-year metadata, and noncontiguous intervals abstain. Metadata labels never bypass interval checks.

## Policies and ablations

`from_scratch_metadata_solver` and `contract` are retained old policies for comparison. `calendar_ordinary` is the new rule set. `calendar_no_availability` removes only availability checks, demonstrating wrong accepted answers on pre-release cases. `calendar_no_unit_normalization` removes only unit normalization, demonstrating wrong accepted answers on billion-vs-million representations. Results are development comparisons, not causal estimates.

## Observed development results

| Policy | Correct answers | Wrong accepted answers | Safe abstentions | Unnecessary abstentions |
| --- | ---: | ---: | ---: | ---: |
| Old metadata solver | 2 | 0 | 3 | 4 |
| Old conservative contract | 1 | 0 | 3 | 5 |
| Calendar ordinary validator | 6 | 0 | 3 | 0 |
| No availability | 6 | 3 | 0 | 0 |
| No unit normalization | 3 | 3 | 3 | 0 |

The full result includes raw per-case outputs and per-issuer metrics. Each issuer contributes two answerable cases and one selected pre-release abstention. The new validator answers both answerable representations for each issuer and abstains on the selected pre-release case. This is local development evidence for these exact exposed cases, not evidence that the duration rules generalize.

The full experimental suite passed 57 tests, including nine calendar tests with mutation cases for semantics, labels, intervals, availability, units, and fixed-input integrity. The final reference and reproduction are compared as full JSON payloads under the recorded environment. The earlier `results.json` predates the final implementation/test bytes: its policy results match, but its disk-code hashes differ, causing the initial full-equality check to fail. That failure is retained in `initial_execution_manifest.json` and `initial_equality_failure.txt`; it is not counted as a successful reproduction. The final receipt is `execution_manifest.json`, generated by `python experiments/artifacts/iteration15_calendar/reproduce.py`.

## Limitations

There are nine dependent scenarios across three annual pairs. Publication dates are selected date-only availability conventions, not earliest-publication or historical-archive proofs. Source-derived values are verified by existing loaders, while several fiscal starts and metadata are author-constructed. No FX, restatement, intraday availability, market decision, autonomous extraction, learned evolution, or general threshold claim is made.
